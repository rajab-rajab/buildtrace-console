BuildTrace

A local CustomTkinter developer console that visibly generates, inspects, and verifies a SQLite-backed Python task-manager project.

What the app does

Choose a path
Use live OpenAI generation when a key is available, or the reliable offline template.
Make work visible
Show five build steps and tabs for the three generated files.
Prove it runs
Initialize the generated SQLite app and run controlled CLI commands in the terminal.

One build, traced through the code

Reference code route

This is a reference route, not a claim that you toured every line interactively.

  1. src/ui/build_input_panel.py → BuildInputPanel
    This creates the editable prompt and the two deliberate entry points: live generation or the offline template.
  2. src/app_shell.py → start_live_build(), _begin_build(), _poll_ui_events()
    This keeps network and file work off the GUI thread, then returns progress, file tabs, and completion events safely to the visible interface.
  3. src/build_controller.py → build_live() and src/generation_service.py → generate()
    The live JSON payload is parsed and locally validated. If a key, timeout, or network call fails, the same controller deliberately uses templates/task_manager_fallback.json and still writes and runs real files.

To change this, start here

  • Change the fixed demo prompt or button labels in src/ui/build_input_panel.py.
  • Change the generated task-manager contract in templates/task_manager_fallback.json; update tests/test_generated_task_manager.py with it.
  • Change output validation rules in src/payload_validator.py; the regression coverage starts in tests/test_payload_validator.py.
  • Change live-generation behavior in src/generation_service.py; verify its contract with tests/test_generation_service.py.

A practice to reuse

BuildTrace’s core promise is not merely “call an AI model”; it is “show a user a real, inspectable result.” That is why tests/test_build_controller_live.py proves an API failure still produces a validated fallback project, and tests/test_offline_e2e.py proves the files initialize for real. For another agent-backed app, identify the visible proof first, then write one check for the live path and one for the safe fallback.
